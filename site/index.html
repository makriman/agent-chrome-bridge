Agent Chrome Bridge by makriman

Give Grok Bot and other agents your Chrome.

Agent Chrome Bridge is an open-source Chrome extension plus a small Node bridge that listens only on 127.0.0.1:18474. You sign in to a site in your normal Chrome, click Arm tab, and your agent can inspect and operate that one tab. Your session stays in your browser. Cookies are never exported.

Cloud Chrome is not your Chrome

Agents that run in datacenters, CI, or hosted browser farms often hit Cloudflare "Verify you are human", "Access denied", or other bot-score walls that your own signed-in Chrome tab already passed. Exporting cookies or standing up a remote relay hands your session to someone else. Agent Chrome Bridge takes the other route: the agent works inside the tab you armed, on your machine, through a loopback control plane.

Install and quick start

You need Google Chrome, Node.js, and a local checkout of the repository.

  1. Clone and start the bridge: 
    git clone https://github.com/makriman/Agent-Chrome-Bridge.git
cd Agent-Chrome-Bridge
npm install
npm run bridge
  2. Open chrome://extensions, turn on Developer mode, click Load unpacked, and choose the repository's extension/ folder.
  3. Open the site you want the agent to work on and sign in as you normally would.
  4. Click the Agent Chrome Bridge toolbar icon, then Arm tab. That arms the active tab for 30 minutes.
  5. Check the connection from the repo folder: 
    node bridge/control.mjs doctor
node bridge/control.mjs status
  6. Let your agent drive the armed tab, for example: 
    node bridge/control.mjs inspect 120
node bridge/control.mjs click-ref ref_abc123
node bridge/control.mjs screenshot artifacts/current.png

After any bridge restart, arm the tab again. Full command reference and workflow runner docs are in the README and SKILL.md.

How it works

  1. Arm one tab. You arm the active http or https tab from the popup. Agent commands run only on that tab. The arm lasts 30 minutes. The popup Stop button disarms it, and so does node bridge/control.mjs stop. An agent cannot arm a tab. After a bridge restart, arm the tab again.
  2. Localhost bridge. A Node server binds to 127.0.0.1:18474 only. It queues commands from the CLI (bridge/control.mjs) or the JavaScript SDK (bridge/sdk.mjs) and the extension polls that loopback address. Control requests carry a local token kept in a file on your machine. There is no remote relay in this repository.
  3. No cookie export. The project does not read or export cookies or passwords. inspect omits the value of inputs whose type, name, id, autocomplete, label, or placeholder looks like a password, email, phone, card, OTP, token, or similar secret. Reported URLs keep the origin and path, and drop the query string and fragment.
  4. Inspect, act, verify. inspect returns visible interactive elements with refs. Use click-ref, fill-ref, type, key, nav, scroll, and screenshot. Repeatable jobs can run through bridge/run-workflow.mjs with --dry-run, --resume, and approval gates the workflow asks for before a final action.

Chrome may show its debugger banner while commands run. That is expected.

Use cases

  • Cloudflare-gated pages. When a datacenter, CI, or hosted browser is stopped by "Verify you are human" or "Access denied", and your own signed-in Chrome is not.
  • SSO and other sign-in walls. You complete sign-in, including any multi-factor prompt, in your normal Chrome profile. The agent then works in the tab you armed. The documented path is that you sign in yourself. The project does not export that session.
  • Partner portals and admin consoles. Pages a datacenter browser cannot pass. Shopify Partners is the documented proof point for that class of gate, not the product.
  • Draft, then approve. A workflow can prepare a form or reply and stop on an approval gate before the final submit. See the support-reply example in the repository.

Proof point, not the product: the repository's cookbook documents working Shopify Partners pages through an armed tab, a class of site that blocked datacenter Chrome. See docs/partners-cookbook.md.

Security model

  • Loopback only. The bridge binds to 127.0.0.1. There is no remote relay in this repository.
  • You arm it. An agent cannot arm a tab. Only http and https tabs can be armed, and one tab is armed at a time. Arming a different tab replaces the previous arm. Closing the armed tab disarms it.
  • No credential export. The project does not export cookies, passwords, or session tokens. Keep the local bridge token file private. Do not paste it into chat or commit it.
  • Redaction by default. Inspection omits values of password, email, phone, card, OTP, token, and similar fields, and reports URLs as origin plus path.
  • Final actions can wait for you. A workflow can call an approval gate before sending, purchasing, deleting, or changing settings. That gate is something the workflow asks for. The bridge does not silently classify every click.
  • Broad browser permissions. The extension requests activeTab, debugger, scripting, storage, and tabs, plus host access to all URLs so it can drive the armed tab. A content script is declared for http and https pages. Commands run only while a tab is armed, and only on that tab. Load the extension only from a checkout you trust.

The current version is 0.1.0. Open work is listed in the roadmap. To report a vulnerability, follow SECURITY.md and do not open a public issue.

Not to be confused with

There is a different project with a similar name: MichaelZelbel/chrome-agent-bridge. Both let an agent use a logged-in Chrome. They are built differently. The comparison below is taken from each project's public README.

Agent Chrome Bridge (this project)MichaelZelbel/chrome-agent-bridge
ShapeChrome extension plus a Node bridge bound to 127.0.0.1:18474. No remote relay in this repository.HTTP gateway (Express and Playwright). Default bind is 0.0.0.0 port 3007. Their README says Chrome's debugging port stays on 127.0.0.1, and the gateway is the network surface.
Which ChromeA tab in your own Chrome, which you explicitly arm. One tab at a time.A dedicated Chrome window with its own persistent profile, launched by that project. Their README says to use that profile rather than a daily personal browser.
Where the agent runsOn the same machine, via the local CLI or SDK, talking to 127.0.0.1.Their README describes a remote agent, for example on a VPS, reaching the gateway over a private network such as Tailscale.

Pick the one that matches your setup. If you want an agent to work in the Chrome you already use, one armed tab at a time, on localhost, that is this project.

FAQ

Does it export my cookies?

No. The repository does not read or export cookies. Authentication stays in your Chrome profile. The agent operates the tab you armed.

Does it send my browsing data to a cloud service?

No. The bridge binds to 127.0.0.1. This repository has no remote relay.

Can the agent use all my tabs?

No. One tab is armed at a time, and you choose it by arming the active tab. The arm lasts 30 minutes. You can disarm it from the popup Stop button or with node bridge/control.mjs stop.

Is there an MCP server?

No. This repository has no MCP server. You drive the bridge with the CLI (bridge/control.mjs) or the JavaScript SDK (bridge/sdk.mjs).

Which agents work with it?

It was built for Grok Bot. Any agent that can run local shell commands or Node on the machine where Chrome is running can use the same CLI or SDK.

Is it on the Chrome Web Store?

The repository documents loading the unpacked extension/ folder from chrome://extensions. It does not ship a Web Store package.

Why is it named codex-chrome-bridge in some places?

That was the earlier name. The repository is now makriman/Agent-Chrome-Bridge. The npm package name, an auth header, and some environment variables keep the old name for compatibility.
